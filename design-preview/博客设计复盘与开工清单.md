# 博客 / 站点页设计复盘与开工清单

> 来源：Home v3 → Blog v1–v6；Home v3 → Diary v1–v6 迭代讨论与返工经验  
> 定稿预览：[`Blog v6.html`](./Blog%20v6.html) · [`Diary v8.html`](./Diary%20v8.html)  
> 通用时段背景：[`shared/period-atmosphere.css`](./shared/period-atmosphere.css)（可挂任意房间舞台）  
> 用途：**进 Vue 前必读**；以后做日记、知识库、实验室等新房间时，开工第一天就按本文自检，避免同一类问题拖到后期才暴露。

---

## 0. 一句话结论

**视觉系统可以继承，但「构图契约」必须逐页兑现。**  
只把列表页做满、其它页居中瘦长条 + 两侧空白，等于半成品。组件比例、画布尺寸、Skill 流程、风格锚点、布局方法、装饰节奏——这些都是**开工问题**，不是收尾打磨项。

---

## 1. 我们实际踩过的坑（按发生顺序）

| 阶段 | 现象 | 根因 | 后来的修法 |
|------|------|------|------------|
| v1–v3 | 有 token、有五屏，但「长条感」强 | 搜索/时间线/卡片横向拉满；缺少主页式疏密与装饰 | v4 起反长条：限宽、小卡、装饰 |
| v4–v5 | 列表渐好，其它页仍「空」 | 只打磨列表；详情/发布/分类/标签仍中栏独大 | v6 全页统一三栏壳 |
| 早期筛选 | 点分类/标签只在列表过滤 | 独立归档页与列表入口未打通 | 列表点击 → 进筛选页 |
| 分类 vs 标签页 | 两套布局，不能同选 | IA 按路由拆成两页，忽略组合筛选 | 合并为单一「筛选」页 |
| 多选 | 单选高亮，无复选框 | 把「筛选 UI」当成导航装饰而非表单 | 复选框 + 芯片可单删 |
| 清空条件 | 取消光了却停在空页 | 未定义「无条件」的落点 | 全取消 → 回列表首页 |
| 收尾 | Esc、焦点、下一篇不可点等 | 交互契约未写进开工清单 | v6 定稿补齐 |

**教训：后期讨论的细节，大半本该在 Kickoff 写成硬约束。**

## 2. 开工必须先对齐的六件事

### 2.1 使用 Skill（流程，不是摆设）

适用：[`web-design-engineer`](../.agents/skills/web-design-engineer/SKILL.md)

| 步骤 | 必须产出 | 本项目对应 |
|------|----------|------------|
| Mode | Extension / Preserve / Overhaul | **Extension**：延展 Home v3，不是另起一套站 |
| Design Read + 五表盘 | 写进计划再动码 | brand-fidelity ≥ 9；画布按 1920×1080 |
| Checkpoint 1 | 设计系统确认后再编码 | token、字体、阴影、缓动照抄主页 |
| 版本策略 | v1 骨架 → 反馈 → vN | 保留 `Blog v1`…`v6`，不覆盖旧版 |
| 预览介质 | HTML 可打开预览 | **先 HTML，后 Vue**；未定稿不进业务仓大改 |

**禁止**：口头说「按 Skill」却跳过 Design Read / 锚点文件 / 全页构图自检。

### 2.2 风格参考（锚点要可打开）

| 项 | 约定 |
|----|------|
| 主锚点 | [`Home v3.html`](./Home%20v3.html) — 二次元清新站：樱粉/紫/薄荷、点阵、薄雾径向、ZCOOL KuaiLe |
| 继承内容 | CSS 变量、顶栏品牌、时段主题（晨/午/暮/夜）、玻璃卡、弹簧缓动、Tweaks 习惯；**时段背景优先复用** [`shared/period-atmosphere.css`](./shared/period-atmosphere.css) |
| 禁止另起炉灶 | 紫色科技渐变墙、Inter/系统默认展示字、大面积单色块、emoji 当图标、左边竖条强调卡 |
| 渐变 | 克制薄雾径向（跟主页），禁止通栏炫彩渐变 |

进 Vue 时：从 Home / Blog 预览抽 **同一套 design tokens**，博客房间不得私自换色相。

### 2.3 屏幕与画布（比例问题的一半在这里）

| 项 | 约定 |
|----|------|
| 设计画布 | **1920×1080** 固定舞台；`transform: scale` 适配视口 |
| 首屏目标 | **一屏一构图**，不是无限长文档流（预览与「杂志感」页面） |
| 溢出策略 | 列表：分页 / 点翻；正文区：栏内 `overflow`；禁止整页靠外层狂滚掩盖构图失败 |
| 对照 | 打开主页与博客预览时，舞台圆角、阴影、边距应同一量级 |

**自检句**：缩小到笔记本上看，第一眼是「一个房间」，还是「一条被拉长的后台表格」？

### 2.4 组件比例（反长条）

| 坏模式 | 好模式 |
|--------|--------|
| 搜索条 / 筛选条 / 时间线通栏拉满 | 工具进侧栏；主区有明确栏宽预算 |
| 卡片 `1fr` 拉成扁长条 | 小而密的 bento / 网格；特色卡用 span，不是整行一条 |
| 表单输入框横贯 1920 | 主栏写作 + 侧栏元数据；输入有可读宽度 |
| 详情正文 `max-width` 居中后两侧真空 | 不是「加 max-width」完事，而是 **侧栏吃掉空白** |

经验值（Blog v6，可调但需全页统一）：

```text
--col-side: 248px   /* 左：工具 / 筛选 / 返回 */
--col-deck: 300px   /* 右：杂志架 / 统计 / 下一篇 */
主栏: minmax(0, 1fr)
gap ≈ 22px；页边距 ≈ 48px
```

### 2.5 布局方法（全页同构，再谈个性）

**默认壳（公开内容页）：三栏**

```text
[ 侧栏 side ]  [ 主内容 main ]  [ 装饰/上下文 deck ]
```

| 页面类型 | 左 | 中 | 右 |
|----------|----|----|----|
| 列表 | 关于 / 搜索 / 分类入口 / 标签入口 | 标题 + bento 或时间线 + 分页 | 杂志翻页书架 |
| 详情 | 返回 / 目录 / 作者 | 封面 + 正文 | 相关 / 标签 / 下一篇杂志卡 |
| 发布 | 返回 / 提示 / 状态 | 标题摘要正文 | 封面分类标签 / 检查清单 |
| 筛选 | 返回 + **分类复选 + 标签复选** | 结果网格 + 条件芯片 | 统计 + 当前条件杂志卡 |

**规则**：

1. 列表满意 ≠ 其它页可以瘦中间、空两侧。  
2. 新开一页，先套三栏壳，再填内容。  
3. 若某页不适合三栏，开工时书面说明例外（如全屏沉浸阅读），默认不例外。

### 2.6 装饰与「房间感」（每页都要有）

装饰不是列表页专利。每页至少具备：

| 层级 | 示例 |
|------|------|
| 舞台氛围 | 与主页同源的点阵、径向雾、时段主题 |
| 局部道具 | 胶带 tape、印章、日历块、贴纸 Vol、杂志书脊 |
| 右栏戏份 | 书架翻页 / 下一篇 / 筛选徽章 / 草稿杂志卡 —— **禁止空 dec 栏** |
| 动效 | 入场 rise、翻页跟手势方向、喜欢轻弹；`prefers-reduced-motion` 要收 |

**自检句**：把顶栏品牌抠掉后，这一屏还像「某某の小站」的同一个房间吗？两侧还有没有「被遗弃的空白」？

## 3. 信息架构与交互（比配色更容易返工）

以下应在 **画第一版 HTML 前** 写进范围，而不是做完五屏后再改：

### 3.1 筛选：合并，不要假两页

- 分类与标签是 **同一筛选上下文**，不要做成互斥的两个「只能选一类」的独立成品页。  
- 列表侧栏点击分类/标签 → 进入 **同一筛选页**，并带上当前勾选。  
- 多选：真复选框；类内并集，分类×标签同时勾选时用交集（或开工时明文约定）。  
- 条件展示：芯片可单项删除。  
- **全部取消 → 回列表首页**（不是留在空结果页）。

### 3.2 导航契约

| 动作 | 预期 |
|------|------|
| 点品牌 | 回列表（或站点首页，开工时定一条） |
| Esc | 先关弹层，否则非列表页回列表 |
| 详情分类/标签 | 可跳进筛选 |
| 详情「下一篇」 | 可点击，不是纯装饰 |
| 列表「全部」 | 清空筛选并留在列表 |

### 3.3 页面范围

开工问卷（必答）：

1. 本轮覆盖哪些路由？（列表 / 详情 / 发布 / 筛选 / …）  
2. 后台管理是否同一视觉？（本站约定：**公开页清新风；后台可另套工作台**，不要硬塞二次元。）  
3. 定稿标准是「每页都达列表同等密度」，还是允许部分页占位？

**未列入范围的页，不要在预览里做半套壳让人误以为已定稿。**

## 5. 推荐交付节奏（避免「一次做五屏但只有一屏能看」）

1. **Kickoff 文档**（本文清单勾完）  
2. **v1**：全页三栏壳 + token + 切页（允许主区占位，但 **壳与装饰位要在**）  
3. **v2**：列表做满（用户最敏感的一页）  
4. **v3**：其余页按同一壳填满，不做「瘦中间」  
5. **v4+**：交互契约（筛选合并、多选、回落）  
6. **定稿**：动效与键盘/焦点等收尾  
7. **Vue**：只移植定稿构图与契约，不在移植时重新发明布局  

**错误节奏**：v1–v3 五屏都「有内容」但结构是通栏长条 → 用户否定后整体翻修。  
**正确节奏**：先锁构图契约，再填密度。

## 6. Vue 移植时要对齐的契约（下一阶段）

移植 [`Blog v6.html`](./Blog%20v6.html) 时，请保持：

| 契约 | 说明 |
|------|------|
| 布局壳 | `side \| main \| deck` 与 CSS 变量列宽 |
| 筛选 IA | 单页组合筛选；芯片；清空回 `/blog` |
| 视觉 token | 与 Home 共用，博客不另起 theme |
| 列表密度 | bento / 分页单屏，而不是无限瀑布拉长条 |
| 详情/发布 | 同样三栏，右栏有真实信息架构 |
| 路由映射 | 列表 `/blog`；详情 `/blog/:id`；发布 create/edit；筛选可用 query（如 `?cats=&tags=`）代替独立 category/tag「空壳页」 |

独立路由 `/category/:name`、`/tag/:name` 若保留，应 **渲染同一筛选页组件** 并预勾条件，而不是两套 UI。

## 9. 日记房间（Diary）复盘与开工增补

> 预览链：`Diary v1`…`v8` · 当前参考 [`Diary v8.html`](./Diary%20v8.html)  
> 时段背景：复用 [`shared/period-atmosphere.css`](./shared/period-atmosphere.css)，组件只跟 `--craft-*` 色调  
> 模式：Home v3 **Extension**（房间强调色 = 淡紫 lilac `#c79ae0`）  
> 路由意向：列表 `/diary` · 详情 `/diary/:id` · 写作 `/diary/write`（编辑选中日）

博客清单的画布、三栏壳、反长条、先 HTML 后 Vue **全部适用**。本节只记日记特有的坑与硬约束——**开工日记时 §2–§4 + 本节一起勾**。

### 9.1 一句话

**空白用「手账道具」填，不要用控件纵向/横向拉满来填。**  
日记页的辨识度来自选日阅读 + 一日一篇 + 草稿本，而不是再做一套博客式卡片瀑布。

### 9.2 实际踩过的坑（Diary v1→v6）

| 阶段 | 现象 | 根因 | 后来的修法 |
|------|------|------|------------|
| v1 | 日历过大，像仪表盘 | 把「重要」做成「占满」 | 日历收成选日控件，宽度/格高有上限 |
| v2–v3 | 日历过小或中间仍空 | 只缩控件、没定义空白归谁 | 空白交给手账装饰，不继续堆功能 |
| 中期 | 心情筛选占左栏却几乎不用 | 把未验证的过滤做成正式 UI | **砍掉筛选 → 改左手账角装饰** |
| v3 | 中间被拉成通栏卡片墙 | 套用博客「列表多卡」惯性 | **一日一篇**：中栏 = 选中日正文纸，不是卡网格 |
| v3 | 右栏便签绑死某一天 | 草稿与正式日记职责不清 | 右栏 = **通用草稿本**（不绑日）；落笔靠「编辑选中日」 |
| v4 | 日历格被纵向拉高填满列 | `1fr` / 固定 6 周硬撑高度 | 格高固定（约 34px）；只渲染实际周数 |
| v4–v5 | 左列日历以下真空 | 认为装饰是收尾 | **日历自然高 + 下方手账 scrapbook 吃剩余** |
| 打磨前 | 装饰像通用贴纸，不像日记 | 装饰与模块特色、选中态脱节 | 票根/火漆/日期章/压花/四季签 **跟选中日、心情联动** |
| 时段 | Tweaks 换晨午昏夜只变背景 | 时段 token 只接到 page 渐变 | 胶带、和纸、钢笔、火漆、拍立得天空、玻璃、引言 **跟时段变** |
| 交互收尾 | 能点但不能「用」 | 未写键盘/双击/自动存契约 | 单击读、双击写、←→、Enter、T、Esc、Ctrl+S、草稿防抖存 |

**教训（相对博客多出来的）：**

1. **控件比例三连错**：过大 → 过小 → 被 stretch。正确姿势是 **自然尺寸 + 装饰吃空白**。  
2. **没用的过滤不要占栏**：先装饰占位，真有数据与诉求再升级成控件。  
3. **房间特色要写进装饰语义**：日记 = 手账/票根/火漆/压花，不是随便几块玻璃卡。  
4. **时段是整房气氛，不是只换 `--page-*`**。

### 9.3 产品与 IA（开工必答）

| 项 | 约定 |
|----|------|
| 粒度 | **一日一篇**（同一天只有一篇可编辑） |
| 列表中栏 | 展示 **当前选中日** 的标题 + 正文（纸页感），不是多日卡片墙 |
| 日历 | 只负责选日 / 标有文；不纵向拉格；下方可放手账装饰 |
| 右栏草稿 | **通用草稿本**，不绑定某日；写入正式日记经 CTA「编辑这篇 / 写这一天」 |
| 右下 CTA | 始终针对 **当前选中日**（有文→编辑；无文→开写） |
| 左栏 | 关于 + 写今日 + **手账角装饰**（勿再塞未验证的 mood filter） |
| 详情 / 写作 | 同一三栏壳；右栏要有戏份（心情章、下一篇、检查清单、草稿对照等） |

### 9.4 布局经验值（Diary）

与博客同壳，中栏内再分：

```text
三栏壳：--col-side:248px | main | --col-deck:300px

list 主区：
  mid-left  ≈ minmax(320px, 380px)   /* 上：日历自然高；下：手账装饰 flex:1 */
  day-reader ≈ 1fr                   /* 选中日正文纸 */
```

**禁止**：用拉高 `.cal-cell`、强制 6 周空白行、或把 day-reader 做成扁长卡片条来「填满」。

### 9.5 装饰节奏（日记特色）

| 层级 | 日记侧做法 |
|------|------------|
| 舞台 | 同源点阵 / 径向雾 / 时段；点缀色随时段变 |
| 左栏手账角 | 拍立得、心情条、印章、时段芯片与引言 |
| 中栏 scrapbook | 四季书签、翻开页、压花、日期章、票根、火漆、和纸、笔与夹 |
| 右栏 | 日期徽章 + 月统计/连续天 + 草稿本 + 编辑 CTA |

装饰可点（盖章、翻转等）可以有趣味反馈；**新交互以后再加**，但不要把装饰做成假按钮（能点却无响应）而不标明 stub。

### 9.6 交互契约（列表定稿已对齐的）
