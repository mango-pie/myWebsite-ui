# MIKU PULSE 播放器改进意见

> 基于对全部 7 个视图（Stage / Discover / Search / Library / Playlists / Settings / AudioLab）、
> 核心状态机 `usePulsePlayer.ts`、发现页 `usePulseDiscover.ts`、网易云集成 `neteaseMusic.ts`、
> 多平台集成 `metingMusic.ts` 的通读整理。
> 现状：舞台主页完成度最高（视觉/动效/交互都已成体系），其余页面功能骨架齐全但存在明显缺口与粗糙处。

---

## 一、功能缺口（按优先级）

### P0 · 体验硬伤，建议优先修

| # | 问题 | 现状 | 建议 |
|---|------|------|------|
| 1 | **本地导入刷新即丢** | 本地文件用 `URL.createObjectURL` 播放，`persistMeta()` 明确注释 "local blob URLs can't persist"，刷新后本地曲目全部清空，需重新导入 | 用 **IndexedDB** 持久化导入的音频文件本体（File → Blob → IDB），刷新后恢复播放；同时支持本地曲目的「仅存元数据不存文件」开关，避免大文件占满配额 |
| 2 | **发现页/热搜/歌手/专辑/歌单搜索单点依赖网易云** | `loadHome()` 四个 Promise 全部来自网易云（每日推荐/新歌/精选歌单/新碟），热搜、歌手/专辑/歌单搜索也是网易云独有；网易云挂了发现页整页报错 | 把已接入的 **meting-lite（QQ/酷狗）扩展进发现页**：QQ 推荐歌单、QQ/酷狗热歌榜、新歌速递多源合并；热搜做多源降级（网易云失败自动切 QQ）；各区块失败局部降级而不是整页 error |

### P1 · 明显缺失，建议排期

| # | 缺口 | 说明与建议 |
|---|------|-----------|
| 3 | **「电台」名不副实** | 导航叫「歌单与电台」，但 `api-enhanced` 全套 `dj_*` 接口（DJ 推荐、分类、节目、订阅）前端零使用。接入「网易云电台」区块：推荐电台 + 分类浏览 + 播放节目 |
| 4 | **排行榜缺失** | 网易云 toplist、QQ 巅峰榜都没接入。发现页加「排行榜」区块，点开看榜/一键播放 |
| 5 | **无歌曲详情面板** | 点搜索结果直接开播，无法查看「歌手信息 / 所属专辑 / 相似歌曲 / 加入歌单 / 下载」。建议加右键/更多按钮 → 详情抽屉 |
| 6 | **批量管理缺失** | 曲库/歌单无多选、批量下载、批量移除；本地歌单内不能拖拽排序（队列有拖拽，歌单没有）。建议歌单行加拖拽手柄 |
| 7 | **EQ 无预设** | `PulseAudioLabView` 只有「恢复平直」，10 段 EQ 有完整链路却无预设。加 流行/摇滚/爵士/古典/重低音/人声 一键预设 |
| 8 | **无 Media Session 集成** | 浏览器锁屏/系统媒体栏（切歌、进度、封面、播放/暂停）完全没接。接入 `navigator.mediaSession`，桌面和移动端体验质变 |
| 9 | **下载能力偏弱** | 有「下载本页/单曲 + 含歌词 + 含 MV」的框架，但无格式选择（mp3/flac/原始）、无命名规则配置、失败只有 `downloadFailedTitles` 列表无重试入口 |
| 10 | **本地歌词仅手动** | 曲库有「选 lrc 文件」入口，但已有 `lookupOnlineLyrics()`（网易云搜索匹配）未做自动兜底。本地曲目播放时若歌词为空，自动尝试在线匹配，失败再提示手动 |
| 11 | **本地歌单无封面/无排序** | 本地歌单只有字母块封面，不能换封面、不能排序。建议：颜色/渐变可选 + 拖拽排序 + 歌单信息编辑 |
| 12 | **登录引导缺失** | 「每日推荐登录后更准」「高码率需登录」等提示散落各处，但登录入口藏在设置页深处。建议未登录时在发现页顶部显示一条可关闭的引导条 |

### P2 · 锦上添花

- **AI 歌单**：项目是 Ai-scene 定位，可做「AI 推荐」——输入心情/场景/关键词，本地或调用后端 LLM 生成歌单（从多源搜索聚合），一键入队
- **听歌统计**：已有 `historyIds` 最近 60 首，可扩展周报/年度总结（Top 歌手、Top 歌曲、时长）
- **跨设备同步**：收藏/歌单/设置全在 localStorage（且 localStorage 有 5MB 上限，曲库大了会爆），可同步到站点后端账号
- **沉浸模式**：快捷键隐藏全部 chrome（侧栏/底栏/顶栏）只剩舞台
- **多平台歌单导入**：粘贴 QQ 音乐/网易云歌单链接 → 解析 → 一键导入本地歌单
- **场景电台**：学习 / 专注 / 睡眠等固定场景流（多源聚合歌曲 + 淡入淡出）
- **切歌/下载完成通知**：Notification API，窗口后台化时也不错过
- **音乐闹钟/定时停止**：播放器侧定时器，睡前场景实用

## 二、UI / UX 表现问题（重点）

### 2.1 页面气质割裂
- 舞台页是「作品级」的沉浸体验（自定义动效、频谱、MV 调度、唱片氛围），而其余六页统一是「卡片 + 面板」的后台观感，**落差明显**。建议为 Discover 页引入与舞台同源的背景氛围（弱化频谱/粒子只作底色），Library/Playlists 至少统一 spacing 与圆角语言。
- 封面 fallback 大量使用字母块（`39 / ALB / ART / TRK / NET / LOC / QQ / KG`），视觉单调。可改为**按曲目 tone 渐变底 + 音符图标**，与整体霓虹风格一致。

### 2.2 空状态与文案
- 文案大量暴露技术名词：「请确认 netease-api 代理已启动」「需 /netease-api 代理可用」「经 /netease-api 代理」。普通用户看不懂，建议统一改为「音乐服务未连接，请检查启动器窗口」级别的人话。
- 空状态引导不统一：曲库/舞台空态有按钮引导，发现页「暂无推荐歌单」只有一行字。**所有空态都应有：一句原因 + 一个可执行动作**。
- 舞台空态文案「搜一首网易云」已过时（现在支持 QQ/酷狗），应改为「搜一首歌，或导入本地音频」。

### 2.3 反馈与加载
- 列表加载只有文字「正在加载…」，无骨架屏；搜索结果加载态整页遮罩。建议列表用**骨架行**，并保留已有结果做「增量加载」而不是清空闪烁。
- `showToast` 只有一种样式，无成功/警告/错误区分；下载完成、加歌单成功、失败原因混在一起。
- 搜索失败/发现失败是**整页错误面板 + 重试**，建议改为局部降级（网易云挂掉时显示本地 + QQ + 酷狗结果，并提示「网易云暂不可用」）。

### 2.4 响应式与触控
- 整体是桌面轨道布局（左侧 rail + workspace + 底部播放器），视图模板中未见明显的响应式断点类；大量 `hover` 才出现的操作（曲目行按钮、舞台悬停封面）在触屏上不可达。PWA 可安装却移动端体验存疑，建议：
  - 加 `@media` 断点：窄屏时 rail 收成底部 tab，操作按钮常驻或 `:focus-within` 显示
  - 触屏长按/双击替代 hover 交互

### 2.5 视觉细节
- 模板中散布大量内联样式（`style="padding: 12px 16px"`、`style="margin-top: 18px"`、`style="grid-column: 1 / -1"` 等），建议收敛为 CSS 工具类，便于统一调整。
- 搜索 `result-row` 信息密度过高：标题 + 歌手 + 专辑 + 来源徽标 + 时长 + 4 个操作按钮挤一行，窄窗口溢出。建议：来源徽标并入封面角标，操作按钮 hover/常驻二态处理。
- 设置页「来源与网络」中 **OpenSubsonic 占位卡（DEMO 徽标）很突兀**：要么实现（接 Navidrome/自建库，其实与本地导入互补），要么移除。
- 底部播放器按钮纯图标无文字，虽有 aria-label 但新手识别成本高；建议常用操作（播放/下一首）加 tooltip，或首次使用时提示。

### 2.6 无障碍
- 已有大量 `aria-label`，但缺：焦点可见样式统一、抽屉/剧场打开时的焦点陷阱与 Esc 收尾、歌词行朗读上下文。播放器是全键盘场景（Ctrl+K 搜索），建议做一次键盘走查。

## 三、技术债务 / 架构建议

1. **状态文件过大**：`usePulsePlayer.ts` 已 1900+ 行，且已有 `composables/pulse/` 目录（`pulseTypes`、`usePulseLyricUi` 等），建议按域拆分：播放核心 / 队列 / 搜索 / 曲库 / MV / 下载 / 本地文件，逐步迁移。
2. **类型桥接层**：`pulseApi.ts` 暴露全量 API 对象给视图，视图 props 类型是 `PulsePlayerApi`；新功能不断往这个接口加字段，建议按域拆 `PulsePlayerApi` 为组合接口。
3. **错误策略统一**：搜索/发现/歌词各处 try-catch 行为不一（有的吞掉、有的 toast、有的整页 error），建议抽一个 `safeFetch` 封装：超时 + 降级 + 统一错误文案。
4. **localStorage 容量**：曲库/队列/收藏都走 localStorage（约 5MB 上限），大量网易云收藏会写爆；建议迁移到 IndexedDB（顺带解决 P0-1 本地文件持久化）。
5. **PWA 离线边界**：workbox 只缓存界面壳，歌词/封面/音频全走网络；本地文件持久化后，离线播放本地曲目可成为卖点。
6. **多平台统一模型**：`neteaseId` / `remoteServer` / `remoteId` 三字段并存是过渡态，建议收敛为 `sourceId: { platform, id }` 的单一远端引用模型，持久化与恢复逻辑会简单很多。

## 四、建议实施路线

| 阶段 | 内容 | 收益 |
|------|------|------|
| **S1（快）** | 本地文件 IndexedDB 持久化；空态/文案人话化；舞台空态文案修正；EQ 预设；Media Session | 高频痛点，几天内见效 |
| **S2（中）** | 发现页多源化（QQ/酷狗榜单与推荐）；排行榜；电台 DJ 接入；歌曲详情抽屉；批量管理 + 歌单拖拽 | 补齐「内容」维度，页面从「能看」到「能用」 |
| **S3（慢）** | AI 歌单；听歌统计；跨设备同步；沉浸模式；移动端响应式重构；无障碍走查 | 差异化卖点，长期打磨 |
